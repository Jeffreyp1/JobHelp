# Bullet Construction (LOAD-BEARING)

The bullet is the unit of resume value. Every bullet earns its line or it goes.

## The XYZ formula

Every bullet must answer: **Accomplished [X], measured by [Y], by doing [Z].**

- **X** = action and outcome.
- **Y** = measurement (number, scale, named adoption, named artifact).
- **Z** = method (tool, technique, scope).

Order can vary, but all three pieces must be present unless the achievement is unmeasurable AND named (e.g., "Authored RFC adopted as the team's API standard").

## The hard rule

The binding constraint: every bullet must contain a number OR a concrete proper-noun artifact.

A number means a count, percentage, dollar amount, scale (users, requests/sec, GB), duration, or speedup factor. An artifact means a named tool, paper, product, dataset, conference, framework, library, or institution. Bullets with neither are vague — restructure or cut.

## Front-load with the F-pattern

Recruiters scan in an F-pattern (top line, second line, then a vertical glance). Front-load the strongest content:

- The first 5-8 words of each bullet should carry the most JD-relevant signal.
- Lead with the concrete verb + object, not the framing.
- The first bullet under each position is the most-read line in the document.

## Length targets

Hard caps depend on the document format. Within those limits:

- Aim for the middle of the target range, not the hard max.
- Two-line bullets must fill at least 70% of the second line (no orphan one-word tails).
- Cut padding before cutting content: drop "in order to," "various," "different," "successfully."

## Forbidden bullet openers

Never start a bullet with any of these:

- Responsible for
- Helped
- Assisted with
- Worked on
- Participated in
- In charge of
- Duties included
- Tasked with
- Involved in
- Supported the team in

Replace with a strong action verb that names the actual accomplishment: Built, Designed, Shipped, Owned, Led, Cut, Doubled, Reduced, Authored, Migrated, Diagnosed, Recovered.

## Verb-ownership match

The verb must match the user's actual ownership:

- **Full-ownership verbs** (Built, Designed, Engineered, Owned, Led) — only if the user did the thing end-to-end.
- **Hedged verbs** (Contributed, Provided, Supported) — for shared or contributing work.

See `02-anti-fabrication.md` for the binding constraint.

## Anti-patterns to fix on the spot

- Bullet ends in "-ing" analysis phrase ("...enabling new capabilities") — restructure to end on a result. See `05-structural-rules.md`.
- No number and no named artifact — add one or cut.
- Vague verb stack ("led, drove, owned, delivered") — pick the one most specific verb.
- Two bullets describing the same achievement at different abstraction levels — merge.

## Per-bullet write protocol

1. Pick the achievement from the user's experience file. Confirm provenance.
2. Identify the JD term that this achievement maps to (see `07-reframing-strategies.md`).
3. Draft using the JD term + concrete number/artifact + verb that matches ownership.
4. Cut padding to land inside char limits without dropping content.
5. Scan: ends on a metric or named artifact? Forbidden opener? Fix before next bullet.

## Self-check before returning

- [ ] Every bullet has a number OR a named artifact.
- [ ] No bullet starts with a forbidden opener.
- [ ] No bullet ends in an -ing analysis phrase.
- [ ] Verb ownership matches the source record.
- [ ] First bullet of each position is the strongest for this JD.
