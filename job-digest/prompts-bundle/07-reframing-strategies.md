# Reframing Strategies

Reframing is the single highest-ROI step in tailoring a resume — it typically moves match scores from ~60 to ~85. Reframe DURING writing, not after. Use the JD's vocabulary from the first draft.

Reframing must stay truthful. Changing what was actually done is fabrication, not reframing — see `02-anti-fabrication.md`.

## The four strategies

### Strategy 1: Keyword Alignment

Preserve meaning, swap terms to match the JD's vocabulary.

- **Before:** "Led experimental design and data analysis programs"
- **After:** "Led data science programs combining experimental design and statistical analysis"
- **Why:** Target role uses "data science" terminology.

### Strategy 2: Emphasis Shift

Same facts, different focal point. Lead with the aspect the target audience grades on.

- **Before:** "Designed statistical experiments...saving millions in recall costs"
- **After:** "Prevented millions in potential recall costs through predictive risk detection using statistical modeling"
- **Why:** Target role values business outcome over technical method.

### Strategy 3: Abstraction Level

Move up or down the technical detail axis depending on the audience.

- **Before:** "Built MATLAB-based automated system for sample evaluation"
- **After (language-agnostic):** "Developed automated evaluation system"
- **After (technical-detail):** "Built automated evaluation system (MATLAB, Python integration)"
- **Why:** Match the JD's appetite for tool-specificity.

### Strategy 4: Scale Emphasis

Highlight the scale dimension the target role weights.

- **Before:** "Managed project with 3 stakeholders"
- **After:** "Led cross-functional initiative coordinating 3 organizational units"
- **Why:** Cross-org complexity reads stronger than headcount for a leadership-track role.

## Confidence bands

| Band | Score | Action |
|---|---|---|
| DIRECT | 90+ | Use with confidence; minor keyword swap if needed. |
| TRANSFERABLE | 75-89 | Strong candidate; reframe via Strategy 1 or 2. |
| ADJACENT | 60-74 | Acceptable with reframing and bridge language (`08-bridge-language.md`). |
| WEAK | 45-59 | Use only if no DIRECT/TRANSFERABLE/ADJACENT exists for that slot. |
| GAP | <45 | Flag to user. Discover, address in CL, or omit. Do NOT force a match. |

## Scoring composition

`Overall = (Direct x 0.4) + (Transferable x 0.3) + (Adjacent x 0.2) + (Impact x 0.1)`

- **Direct match (40%)** — keyword/domain/outcome overlap.
- **Transferable (30%)** — same capability in a different context.
- **Adjacent (20%)** — secondary responsibility or related tools.
- **Impact alignment (10%)** — achievement type matches what the role values.

## Reframe DURING writing

Two failure modes to avoid:

1. **Translation pass.** Drafting in source-domain language and swapping terms after. The first draft locks the framing; the swap rarely fully takes.
2. **Domain leak.** A bullet uses target vocabulary but cites a tool only the source domain uses. Either swap the tool to a JD-matching one (only if truthful) or add a bridge clause.

Write in the target domain's vocabulary from the first sentence.

## When reframing isn't enough

If the band is WEAK or GAP and the gap is binary (the JD requires a tool/method the candidate hasn't touched), reframing cannot save it. Use bridge language for ADJACENT, flag GAP, and surface a discovery question if relevant.
